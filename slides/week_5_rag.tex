\section{Review and Improve the Answer}

\begin{frame}{Generate an Answer, Review It, Then Revise}
  \small A second LLM call checks whether the answer addresses the question and is supported by the documents. Both calls receive the original question and the retrieved passages.
  \begin{center}
  \begin{tikzpicture}
    \node[rag/query,text width=1.9cm] (question) at (0,0) {Student's\\question};
    \node[rag/store,text width=2.2cm] (search) at (2.9,0) {Retrieve\\documents};
    \node[rag/llm,text width=2.4cm] (writer) at (6.2,0) {LLM call 1\\Write an answer};
    \node[rag/llm,text width=2.4cm] (reviewer) at (9.8,0) {LLM call 2\\Review the answer};
    \node[rag/context,text width=2.8cm] (stop) at (9.8,-2.7) {Stop: accepted or\\information missing};
    \draw[rag/arrow] (question) -- (search);
    \draw[rag/arrow] (search) -- (writer);
    \draw[rag/arrow] (writer) -- (reviewer);
    \draw[rag/arrow] (reviewer.south west) -- (8.1,-1.4) -- (6.2,-1.4) -- (writer.south);
    \node[font=\small,align=center] at (7.0,-1.95) {Needs revision:\\send feedback};
    \draw[rag/arrow] (reviewer) -- (stop);
  \end{tikzpicture}
  \end{center}
  \note{This is a fixed answer--review workflow, replacing the earlier model-selected search example. The writer and reviewer can use the same model in separate API calls. Retrieve once using the full original question, then keep the passages fixed while revising the answer. The reviewer checks coverage, factual support and citations. Missing information means the supplied passages are insufficient; it does not prove the information is absent from the entire collection. Stop and report that limitation rather than invent an answer. At most four answer--review attempts are allowed. A review acceptance is a model judgment, not an independent guarantee; evaluate the workflow against the reference answers and sources.}
\end{frame}

\begin{frame}[fragile]{The Answer--Review Loop in Python}
  \small Each attempt makes two LLM calls: \texttt{write\_answer} drafts or revises the answer; \texttt{review\_answer} checks it against the question and passages.
  \par\vspace{0.4em}
  \begin{columns}[T,onlytextwidth]
    \begin{column}{0.63\linewidth}
\begin{lstlisting}[language=Python]
passages = retrieve(question)
answer, feedback = "", ""
for attempt in range(4):
    answer = write_answer(
        question, passages, answer, feedback)
    review = review_answer(
        question, passages, answer)
    if review["status"] != "revise":
        break
    feedback = review["feedback"]
\end{lstlisting}
      \small Four attempts mean at most eight LLM calls.
    \end{column}
    \begin{column}{0.34\linewidth}
      \small The review returns a status and feedback:
      \begin{itemize}
        \item \texttt{accepted}: answer complete and supported.
        \item \texttt{revise}: correct the problems in the feedback.
        \item \texttt{missing\_information}: sources insufficient.
      \end{itemize}
      After attempt four, report any remaining problems.
    \end{column}
  \end{columns}
  \note{The question is the same full student question as before. retrieve is the retrieval function used earlier, with the same corpus; use multilingual embeddings for the French question and English documents. The API functions and complete bounded loop are in examples/week5_retrieval/workflow.py. Bind the Week 3 client and model_name with functools.partial to obtain the call signatures shown here. write_answer returns text; review_answer parses and validates the JSON status and feedback. The full run_loop returns an explicit attempt_limit status when the fourth review still requests revision, and preserves every answer/review pair. No API requests were made to produce this slide. There is no claim that the example requires a correction or that the reviewer is always correct.}
\end{frame}

\begin{frame}{Compare Answers on the Same Student Questions}
  \small Prepare questions about card replacement, Wi-Fi and library services. Read the official pages and record the expected facts and supporting URLs before running the comparison.
  \begin{itemize}
    \item \textbf{Answer quality:} are the instructions correct and complete for the student's situation?
    \item \textbf{Sources:} do the cited pages support the claims and apply to the right faculty or service?
    \item \textbf{Missing information:} does the system explain what it cannot establish?
    \item \textbf{Time and tokens:} count every notebook answer and review call. Record browser timings separately.
  \end{itemize}
  \note{Keep development questions separate from final test questions, as in Week 4. Use the same wording and answer requirements across systems. Store the downloaded snapshot, run date and cited web evidence: live search may see newer pages or a wider collection. Report that difference when explaining results. Include failed/unsupported replies in the report. The reviewing LLM is part of the workflow being evaluated; students verify final answers against the official sources rather than treating its acceptance as the evaluation label. The free browser comparison supplies no notebook API usage record. Keep its timings separate and leave unavailable usage measurements unknown.}
\end{frame}
